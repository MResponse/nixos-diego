#+TITLE: NixOS Configuration — nixos-diego
#+DESCRIPTION: Flake-based NixOS config for an HP ZBook Ultra G1a laptop ("nixos-diego"). Forked from donvini94/nixos-config.

* Overview

This is *MResponse's fork* of [[https://github.com/donvini94/nixos-config][donvini94/nixos-config]]. The fork adds a third host
=nixos-diego= — an HP ZBook Ultra G1a 14" laptop — while preserving
upstream's =dracula= (desktop) and =alucard= (server) hosts on branch
=master=.

** Branch Model

- *=master=* — Mirror of upstream =donvini94/nixos-config=. Inherits the
  upstream =dracula= and =alucard= hosts. *Not built on this machine.*
- *=diego=* — Live reality on the laptop. Adds the =nixos-diego= host
  plus all laptop-specific modules and features. This is what the
  machine actually runs.

A cross-host-switch-guard module (=modules/hostname-safety.nix=,
ADR-0035) refuses =nixos-rebuild switch= to any host whose =hostName=
doesn't match the running =$(hostname)= — protects against accidentally
activating =dracula= or =alucard= on the laptop.

** Hosts

| Host          | Role                          | Hardware                                                | Built here |
|---------------+-------------------------------+---------------------------------------------------------+------------|
| =nixos-diego= | Laptop (this machine)         | HP ZBook Ultra G1a 14", Ryzen AI Max+ PRO 395, Radeon 8060S iGPU — *AMD only, no NVIDIA* | yes        |
| =dracula=     | Upstream desktop workstation  | AMD CPU + NVIDIA GPU                                    | no         |
| =alucard=     | Upstream home server          | Hetzner OpenStack VM                                    | no         |

The flake provides two host-builder functions:
- =mkDesktopHost "hostname"= — Full desktop with Hyprland, home-manager, sops, hosts blocking
- =mkServerHost "hostname"= — Minimal server (host imports what it needs)

For module-level architecture notes see [[file:CLAUDE.md][CLAUDE.md]].

* What the =diego= branch adds on top of upstream

=nixos-diego= layers laptop, gaming, and VR features on top of the
upstream desktop stack. Highlights:

** Session model
- *Hyprland under UWSM* (ADR-0017) — required so the SteamOS session-
  switching machinery (=steamosctl switch-to-{game,desktop}-mode=)
  finds the compositor's =graphical-session.target=.
- *Two-session split* (ADR-0029): Hyprland for desktop / VR / RTS use;
  Gamescope for single-player Gaming-Mode (=SUPER+G= toggles).
- *Gamescope-bound power-mode service* — auto Performance-profile while
  in Gaming Mode, auto-restore on exit.

** Auth & input
- *Fingerprint login* (Synaptics WBF) — wired into SDDM, =sudo=, and
  KeePassXC Quick Unlock.
- *KeePassXC TPM2 auto-unlock* (Plan-0014) — KeePassXC master password
  is sealed to the machine's TPM2 chip; on login KeePassXC opens
  without prompting. Graceful fallback to interactive prompt if no
  sealed credentials exist or TPM2 fails.
- *Qylock SDDM theme bundle* with custom patches:
  - Wayland-cursor fix in =qylock-random= wrapper.
  - =acceptedButtons: NoButton= on sub-theme MouseAreas (29 themes) so
    clicks fall through to the password field.
  - PAM =informationMessage= handler injected into 18 single-line
    themes so the "Place finger on sensor" prompt is visible at the
    greeter.

** VR & gaming
- SteamVR + Steam Link + Pico 4 stack with =CAP_SYS_NICE= re-apply on
  every SteamVR update (works around the Jovian =pkexec= stub
  no-op'ing the original setcap call, ADR-0027).
- Firewall holes for Steam-Link-VR (UDP 10400/10401, TCP 27037).
- RADV cleanup (ADR-0028): =video_encode,sam= replaces the upstream
  =gpl,nggc,sam= — =gpl= and =nggc= are Mesa-default on RDNA 3.5+;
  =video_encode= is required for HEVC hardware-encode for Steam-Link.
- PipeWire low-latency =quantum=256= for VR audio.

** Safety nets
- Cross-host-switch-guard (ADR-0035, see Branch Model above).
- =stevenBlackHosts.blockSocial= carve-outs for WhatsApp Web and Reddit
  — the upstream blocklist otherwise sinkholes them silently.

The full plan/ADR history (Plan-0001 .. Plan-0015) is in the commit
messages on branch =diego=.

* Building

#+begin_src bash
# nixos-diego (the laptop — what you'd actually build here)
sudo nixos-rebuild switch --flake .#nixos-diego

# Or use the fish abbreviation (auto-substitutes $(hostname)):
#   switch        → nixos-rebuild switch --flake ~/nixos-config#$(hostname)
#   boot          → same with `boot` action
#   test-switch   → same with `test` action

# Test build without switching
sudo nixos-rebuild build --flake .#nixos-diego

# Flake management
nix flake update
nix flake check
nix flake show
#+end_src

The cross-host-switch-guard will refuse a =switch=/=test= action if the
target host's =hostName= doesn't match =$(hostname)=. To bypass on
purpose (e.g. =nix build= for a different host's closure, no
activation), use =build= instead of =switch=.

* Secret Management

Uses [[https://github.com/Mic92/sops-nix][sops-nix]] with age encryption.

#+begin_src bash
sops secrets/dmbs.yaml    # Edit encrypted secrets
#+end_src

Config files: =.sops.yaml=, =secrets/secrets.nix=, =secrets/dmbs.yaml=.

* Adding a New Desktop Host

#+begin_src nix
# 1. flake.nix — one line:
newhost = mkDesktopHost "newhost";
#+end_src

#+begin_src bash
# 2. Create the host directory:
mkdir -p hosts/newhost
#+end_src

#+begin_src nix
# 3. hosts/newhost/default.nix — import shared modules + set identity:
{ lib, pkgs, username, ... }:
{
  imports = [
    ../../modules/desktop.nix    # Full desktop stack
    ../../modules/nvidia.nix     # Opt-in: only for NVIDIA GPUs
    ../../modules/gaming.nix     # Opt-in: Steam, Wine, etc.
    ./hardware.nix
  ];
  networking.hostName = "newhost";
  users.users."${username}" = {
    isNormalUser = true;
    extraGroups = [ "networkmanager" "wheel" ];
  };
  system.stateVersion = "24.11";
}
#+end_src

#+begin_src bash
# 4. Generate hardware config on the target machine:
nixos-generate-config --show-hardware-config > hosts/newhost/hardware.nix
#+end_src

#+begin_src bash
# 5. Build and switch:
sudo nixos-rebuild switch --flake .#newhost
#+end_src
